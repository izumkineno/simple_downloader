# 常见问题

> 基线 `0.7.1`。`default = []`，所有可选能力均需显式开 feature；sidecar 后缀为 `*.download.bitcode`；多源无 `weight`。

## 基础使用问题

### Q: 最简单的下载怎么实现？
A: 使用 builder 模式只需要几行代码（无需任何 feature）：
```rust
use simple_downloader::Downloader;

#[tokio::main]
async fn main() {
    Downloader::builder("https://example.com/file.zip", "save_path.zip")
        .download()
        .await
        .unwrap();
}
```

### Q: 如何显示下载进度？
A: 启用 `progress` 后使用 `run()` 并提供进度回调（`match` 必须含 `_` 分支，`#[non_exhaustive]`）：
```rust
Downloader::builder("https://example.com/large_file.zip", "output.zip")
    .run(|total_size, mut info_rx| async move {
        println!("总大小: {} bytes", total_size);
        while let Ok(info) = info_rx.recv().await {
            println!(
                "进度: {:.1}% | 速度: {:.2} MB/s | 已下载: {} bytes | ETA: {:?}",
                info.progress_percent(),
                info.speed_mbps(),
                info.downloaded_bytes(),
                info.eta_secs(),
            );
        }
    })
    .await
    .unwrap();
```
`is_complete()` 仅展示用，终局以 `run()` 返回 `Ok` 为准；`total_size == 0` 时显示 `--` 而非 `0%`。

### Q: 断点续传功能如何使用？
A: 启用 `resume` 后默认即开启（`resume(true)`），下载中断后再次运行相同的代码会自动从断点恢复：
```rust
Downloader::builder("https://example.com/large_file.zip", "output.zip")
    .resume(true)
    .download()
    .await
    .unwrap();
```
断点续传的元数据保存在与输出文件同目录下，文件名是 `输出文件名.download.bitcode`（固定 `64KiB` segment 哈希，非 `.resume`）。成功后自动删除，失败残留下次复用。

### Q: 如何设置并发下载线程数？
A: 使用 `workers()` 方法配置：
```rust
Downloader::builder("https://example.com/large_file.zip", "output.zip")
    .workers(16) // 使用 16 个线程并行下载
    .download()
    .await
    .unwrap();
```
**注意**：如果服务器不支持 Range 请求，或者文件大小小于 1MB，会自动降级为单线程下载。

### Q: 如何配置代理？
A: 单源经 `client_builder`，多源经 `SourceConfig::with_proxies`（需 `proxy` feature）：
```rust
use reqwest::{ClientBuilder, Proxy};

Downloader::builder("https://example.com/file.zip", "output.zip")
    .client_builder(|| {
        ClientBuilder::new()
            .proxy(Proxy::http("http://proxy.example.com:8080").unwrap())
            // SOCKS5 代理: .proxy(Proxy::socks5("socks5://127.0.0.1:1080").unwrap())
    })
    .download()
    .await
    .unwrap();
```
程序也会自动识别 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 等环境变量。

## 功能相关问题

### Q: 多源下载怎么配置？
A: 启用 `multi-source`，使用 `MultiSourceConfig` 配置多个下载源（无 `weight`，旧文已删除；按 `64KiB probe` 实测排序 + 黑名单 `3/30s` 调度）：
```rust
use simple_downloader::{Downloader, MultiSourceConfig, SourceConfig, LaneModel};

let config = MultiSourceConfig::new("output.zip", 32, 0.5)
    .with_sources(vec![
        SourceConfig::new("https://mirror1.example.com/file.zip").with_id("m1"),
        SourceConfig::new("https://mirror2.example.com/file.zip").with_id("m2"),
    ])
    .with_lane_model(LaneModel::PerSource);

Downloader::new_multi(config, Default::default)
    .download()
    .await
    .unwrap();
```

### Q: 如何自定义 HTTP 请求头？
A: 在 client_builder 中配置默认 headers（缺失 UA 时库自动注入 `simple_downloader/x.y.z`，用户配置优先）：
```rust
use reqwest::header::HeaderMap;

let mut headers = HeaderMap::new();
headers.insert("Authorization", "Bearer token123".parse().unwrap());

Downloader::builder("https://example.com/file.zip", "output.zip")
    .client_builder(move || {
        ClientBuilder::new()
            .default_headers(headers.clone())
    })
    .download()
    .await
    .unwrap();
```

### Q: 如何设置请求超时时间？
A: 在 client_builder 中配置超时：
```rust
use std::time::Duration;

Downloader::builder("https://example.com/large_file.zip", "output.zip")
    .client_builder(|| {
        ClientBuilder::new()
            .connect_timeout(Duration::from_secs(10)) // 连接超时 10 秒
            .timeout(Duration::from_secs(120)) // 整个请求超时 120 秒
    })
    .download()
    .await
    .unwrap();
```

### Q: 下载完成后会校验文件完整性吗？
A: 会。`Early-EOF` 在 chunk 侧拦截截断，`monitor` 按 `size()` 落账，收尾再以落盘 `stat len != file_size` 为金标准校验，不一致返回 `Io(UnexpectedEof)` 并保留 sidecar 供 resume 重试。如需哈希校验，请在下载完成后自行计算 MD5/SHA256 与预期值比较。

### Q: 可以暂停和恢复下载吗？
A: 两层语义：进程退出后恢复走 `resume`（segment 哈希校验）；运行期暂停/恢复走 `queue` feature 的 `TaskQueue::pause/resume`（`examples/with_queue.rs`）。单次 `download()` 本身无运行期暂停接口。

### Q: 限速怎么配？`burst` 不填可以吗？
A: 可以。`speed_limit(bps)` 必填，`with_burst` 不填即默认 `64KiB`。`0` / 超 `u32::MAX` / `burst` 无 `speed_limit` 均返回 `InvalidArgument`。全局为硬上限，运行时仅全局维度支持 `reconfigure/disable` 热更。

## 性能优化问题

### Q: 下载速度慢怎么办？
A: 可以尝试以下优化：
1. **增加并发线程数**：
   ```rust
   Downloader::builder(url, path)
       .workers(32) // 对于大文件可以增加到 16-32 线程
       .download()
       .await
   ```
   
2. **使用多源下载**：配置多个镜像源，充分利用带宽。

3. **调整客户端配置**：
   ```rust
   ClientBuilder::new()
       .tcp_keepalive(Duration::from_secs(60))
       .pool_max_idle_per_host(32) // 增加连接池大小
       .build()
   ```

4. **检查网络环境**：确保网络带宽足够，没有被限流（限速启用时会冻结自适应分裂，属预期行为），服务器没有限速。

5. **选择离自己近的镜像源**：延迟越低，下载速度越快。

### Q: 大文件下载时内存占用高怎么办？
A: simple_downloader 对内存使用已经做了优化（`broadcast 4096 + 64KiB/50ms` 限频 + `mpsc 128` 背压 + 相邻写合并），正常情况下内存占用应该是稳定的。如果还是很高：
1. 适当降低并发线程数，减少同时下载的块数
2. 检查是否开启了过多的其他功能
3. 确保使用的是最新版本，我们持续在优化内存使用

### Q: 小文件下载速度慢怎么办？
A: 对于小文件（<10MB），建议：
1. 降低并发线程数到 1-4（`<1 MiB` 本来就会自动单线程）
2. 禁用断点续传功能（`.resume(false)`，需 `resume` feature）
3. 如果批量下载多个小文件，建议走 `TaskQueue` + 连接池复用连接

### Q: 进度更新太频繁导致 UI 卡顿怎么办？
A: 调整进度更新间隔：
```rust
Downloader::builder(url, path)
    .update_interval(1.0) // 每秒更新一次进度，默认是 0.5 秒
    .run(progress_callback)
    .await
```
chunk 侧已有 `64KiB/50ms` 限频，UI 侧只需控制 `MonitorUpdate` 间隔即可。

## 错误处理问题

### Q: 提示 "无法从服务器响应头中获取文件大小" 怎么办？
A: 0.3.1+ 已自动回退单流流式（`total_size=0`），通常不会直接抛错。只有 `HEAD`、`Range 0-0`、`流式 GET` 均失败时才透出 `MissingContentLength`，此时应检查链接/网络，而非强制单线程（单流回退已是单线程）。

### Q: 断点续传失败怎么办？
A: 常见原因和解决方案：
1. **目标文件不存在**（`ResumeTargetMissing`）：补回文件，或删除对应的 `*.download.bitcode` 后重下，或 `resume(false)`。
2. **元数据损坏/版本不一致**（`ResumeMetadata`）：0.7.1 已自愈重建，通常无需手动处理；仍失败再删 sidecar。
3. **服务器文件已变更**：ETag 变更失效暂未接线，如怀疑源已换请手动删 sidecar + 不完整目标文件后重下。
4. **落盘校验失败**（`Io(UnexpectedEof)`）：sidecar 已保留，直接原参数重试即可。

### Q: 提示 "没有可用的下载源"（多源下载时）怎么办？
A: 
1. 检查每个下载源的 URL 是否正确
2. 单独访问每个下载源，确认是否可以正常下载
3. 检查网络连接和代理配置
4. 增加更多可用的下载源
5. 确认各源 `Content-Length` 一致且支持 Range（不一致会被跳过）

无 `max_retries_per_source` 配置，旧文已删除。

### Q: 提示下载失败已达重试上限怎么办？
A: 即 `PermanentFailure`：跨周期 `>30` 熔断、`403/404/416` 不可重试分类、或本地写入击穿。请先看 `ChunkFailed.error` 区分源侧拒绝还是磁盘故障，修正后重试；不要对 `Permanent` 盲重试。

### Q: SSL 证书验证失败怎么办？
A: 优先建议修复证书问题，如果是测试环境或者信任的源，可以临时禁用证书验证（**不安全，生产环境不建议使用**）：
```rust
ClientBuilder::new()
    .danger_accept_invalid_certs(true) // 仅用于测试环境！
    .build()
```

## 开发相关问题

### Q: 如何在生产环境使用 simple_downloader？
A: 生产环境建议：
1. 使用最新的稳定版本（当前 `0.7.1`）
2. 大文件开 `resume`，调用方再包一层指数退避（库内已做 `1s/2s/4s/8s+jitter` + `10s` 延迟 + `30` 熔断）
3. 对 `PermanentFailure/InvalidArgument/ResumeTargetMissing` 分类处理，不盲重试
4. 避免使用不安全的配置（如禁用证书验证）
5. 经 `trace::init_tracing()` + `RUST_LOG` 监控进度和错误情况
6. 对于关键文件下载，下载完成后校验文件哈希值

### Q: 支持同步 API 吗？
A: simple_downloader 是完全基于异步 Tokio 运行时设计的，不提供同步 API。如果需要在同步代码中使用，可以使用 `tokio::runtime::Runtime` 来运行异步代码：
```rust
use tokio::runtime::Runtime;

fn sync_download(url: &str, path: &str) -> Result<(), Box<dyn std::error::Error>> {
    let rt = Runtime::new()?;
    rt.block_on(async {
        Downloader::builder(url, path)
            .download()
            .await
    })?;
    Ok(())
}
```

### Q: 支持 WASM 吗？
A: 目前还不支持 WASM 环境，因为依赖的 reqwest 和 Tokio 在 WASM 环境下有较多限制。

### Q: 支持下载到内存中而不是文件吗？
A: 目前版本只支持下载到本地文件（独立 `file_writer_task` + 有界 `mpsc 128` 背压即为此设计）。如需内存目标，可参考 `file_writer_task` 自行扩展存储后端，但需保留背压语义。

## 其他问题

### Q: simple_downloader 和其他下载库有什么区别？
A: 
- **高性能异步架构**：基于 Tokio 异步运行时，充分利用多核性能
- **内置断点续传**：segment 哈希校验 + 自愈重建 + 落盘金标准
- **多源下载支持**：lane 建模 + probe 排序 + 黑名单隔离
- **智能调度**：动态并发探测 + 指数退避重试 + 限速冻结
- **模块化设计**：通过 Feature flags 可以按需裁剪功能，减小二进制体积
- **简洁 API**：Builder 模式设计，上手简单，同时支持深度定制

### Q: 支持哪些操作系统？
A: 支持 Windows、macOS、Linux，所有 Rust 支持的平台基本都可以使用。

### Q: 商业项目可以免费使用吗？
A: 是的，simple_downloader 使用 Apache 2.0 许可证，可以免费用于商业项目，不需要付费。具体请参考 [LICENSE](../LICENSE) 文件。

### Q: 有计划提供其他语言的绑定吗？
